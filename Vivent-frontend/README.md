# VIVENT Frontend

The VIVENT frontend is a React single-page app for the VIVENT event-management platform. It provides public marketing/info pages, authentication pages, protected event category pages, and dashboards for students, businesses, and admins.

The app talks to the FastAPI backend through [src/utils/api.js](./src/utils/api.js), stores JWT session data in `localStorage`, and uses React Router for protected routes.

## Configuration

The frontend currently reads no Vite environment variables. The backend URL is hardcoded in [src/utils/api.js](./src/utils/api.js):

```js
const BASE_URL = "http://127.0.0.1:8000";
```

To use a different backend host, update that constant.

`vite.config.js` uses:

- `@vitejs/plugin-react`
- `@tailwindcss/vite`
- Dev server port `5173`
- `server.allowedHosts = ["pacific-catlike-fog.ngrok-free.dev"]`

## Routing

Routes are defined in [src/App.jsx](./src/App.jsx).

| Route | Protection | Purpose |
| --- | --- | --- |
| `/` | Public | Home page. |
| `/login` | Public | Student/business login form and forgot-password modal UI. |
| `/signup` | Public | Student/business registration with auto-login. |
| `/events` | Authenticated | Event category overview. |
| `/jobfair` | Authenticated | Job fair listing and application/registration flow. |
| `/foodevents` | Authenticated | Food event listing, ticket purchase, then registration. |
| `/educationalexpo` | Authenticated | Educational expo listing, ticket purchase, then registration. |
| `/about` | Authenticated | About page. |
| `/contact` | Authenticated | Contact page. |
| `/privacy-policy` | Public | Privacy policy. |
| `/terms-of-service` | Public | Terms of Service. |
| `/terms-of-services` | Redirect | Redirects to `/terms-of-service`. |
| `/studentpanel` | Authenticated + `student` role | Student dashboard. |
| `/businesspanel` | Authenticated + `business` role | Business dashboard. |
| `/adminpanel` | Authenticated + server-confirmed `admin` role | Admin dashboard. |
| `*` | Redirect | Sends authenticated users home and unauthenticated users to `/login`. |

`ProtectedRoute` checks local auth state and optional role lists. `AdminProtectedRoute` calls `authApi.me()` and renders the admin panel only when the backend returns `role === "admin"`.

## Authentication Flow

Login is implemented in [src/Pages/Login.jsx](./src/Pages/Login.jsx):

1. User selects student or business account type.
2. The form calls `POST /auth/login`.
3. The returned user role must match the selected account type.
4. The app stores session data in `localStorage`.
5. The user is redirected to `/studentpanel` or `/businesspanel`.

Signup is implemented in [src/Pages/Signup.jsx](./src/Pages/Signup.jsx):

1. User registers as student or business.
2. The form calls `POST /auth/register`.
3. It immediately logs the user in with `POST /auth/login`.
4. Session data is stored and the user is redirected by role.

Stored keys:

- `viventAuth`
- `viventToken`
- `viventAuthRole`
- `viventUser`

Logout removes these keys. The API client also clears them and redirects to `/login` after a `401`.

There is no public admin login page in the frontend. Admin panel access depends on an existing admin token and a successful `GET /auth/me` role check.

## API Client

[src/utils/api.js](./src/utils/api.js) centralizes backend calls. It:

- Adds `Content-Type: application/json`.
- Adds `Authorization: Bearer <viventToken>` when present.
- Serializes request bodies.
- Builds query strings for GET requests.
- Reads backend `detail` or `message` errors.
- Clears auth storage and redirects on `401`.

Service groups currently exported:

| Export | Current backend alignment |
| --- | --- |
| `authApi` | Active: register, login, me, logout. |
| `eventsApi` | Active: list, get, create, update, delete, generate description. |
| `registrationsApi` | Active: register, my registrations, event registrations. `updateStatus` points to a route not currently implemented. |
| `paymentsApi` | Active: initiate, my payments, mock Stripe checkout. `confirm` points to a route not currently implemented. |
| `analyticsApi` | Active: admin, student, business dashboards. `eventAnalytics` points to a route not currently implemented. |
| `adminApi` | Active: pending, approve, reject, dashboard alias. |
| `recordsApi` | Active: my events. |
| `plansApi` | Active: list/create/update/delete. `get` points to a route not currently implemented. |
| `subscriptionsApi` | Active: me, subscribe/switch, cancel. |
| `socialApi` | Legacy: points to `/social-media` routes that are not currently implemented by the backend. |
| `adsApi` | Legacy: generic `/ads` helper paths do not match the current backend ad routes. |
| `aiApi` | `generateDescription` is active; `socialPostIdeas` points to a route not currently implemented. |

Pages currently use the active helpers for auth, events, registrations, payments, analytics, records, plans, admin, and subscriptions.

## Implemented User Interfaces

### Public and Shared Pages

- `Home.jsx`: landing/home page.
- `Eventpage.jsx`: authenticated category chooser.
- `About.jsx`: authenticated about page with image-backed sections.
- `Contact.jsx`: authenticated contact page.
- `PrivacyPolicy.jsx`: public privacy policy.
- `TermsOfServices.jsx`: public terms page.
- `Header.jsx`: navigation, auth controls, dashboard links, profile menu, mobile menu.
- `Footer.jsx`: footer links and social links.
- `FloatingFAQ.jsx`: fixed help button and FAQ modal.

Some public content and category cards use static Unsplash image URLs stored in page code or `src/data/eventCatalog.js`.

### Student Dashboard

[src/Pages/Studentpanel.jsx](./src/Pages/Studentpanel.jsx) implements:

- Protected `/studentpanel` route.
- Dashboard summary from `analyticsApi.studentDashboard()`.
- Joined/current and past records from `recordsApi.myEvents()`.
- Event category navigation.
- Records with recent review filtering.
- Social media promotion/plan view loaded from `/plans`.
- Current subscription lookup through `/subscriptions/me`.
- Plan selection/switching through `/subscriptions`.

### Business Dashboard

[src/Pages/Businesspanel.jsx](./src/Pages/Businesspanel.jsx) implements:

- Protected `/businesspanel` route.
- Dashboard metrics from `analyticsApi.businessDashboard()`.
- Event listing using backend event APIs.
- Event creation with selected plan, category, date, location, max participants, and `venue_details`.
- Event update/delete for owned events or pending submissions.
- Ticket price capture in `venue_details.ticket_price`.
- Records from `recordsApi.myEvents()`.
- Plan listing and subscription selection.

Business category values are mapped to backend values:

| UI value | Backend value |
| --- | --- |
| `job-fair` | `job_fair` |
| `food-events` | `food` |
| `educational-expo` | `educational` |

### Admin Dashboard

[src/Pages/Adminpanel.jsx](./src/Pages/Adminpanel.jsx) implements:

- Protected `/adminpanel` route with server-side role verification.
- Event tables and dashboard sections.
- All-event loading through `eventsApi.list({ page_size: 200 })`.
- Pending event loading through `adminApi.pendingEvents()`.
- Approve/reject actions through admin event APIs.
- Records view with date filtering.
- Post-management UI with locally managed account/post state.
- Client analytics UI using local promotion-plan data.
- Calendar UI state.
- Local add/edit/delete modal UI for admin event rows.

## Event Category Flows

### Job Fair

[src/Pages/jobfair.jsx](./src/Pages/jobfair.jsx):

- Fetches approved `job_fair` events.
- Displays backend event cards with fallback UI data.
- Lets the user apply/register through `POST /events/{event_id}/register`.
- Includes applicant fields and CV file-selection UI.
- Tracks registered event ids with `/registrations/my`.

The selected CV file is not uploaded to the backend in the current implementation.

### Food Events

[src/Pages/Foodevents.jsx](./src/Pages/Foodevents.jsx):

- Fetches approved `food` events.
- Loads completed payments and registrations to determine ticket/registration state.
- Shows a ticket purchase modal using `venue_details.ticket_price`.
- Calls `POST /payments/stripe/create-checkout-session`.
- Redirects to the backend mock Stripe checkout page.
- After a successful ticket payment, allows registration through `POST /events/{event_id}/register`.

### Educational Expo

[src/Pages/Educationalexpo.jsx](./src/Pages/Educationalexpo.jsx):

- Fetches approved `educational` events.
- Uses the same ticket-first flow as Food Events.
- Requires a completed ticket before calling the registration endpoint.

## Ticket-First Registration Rule

The frontend mirrors the backend rule for food and educational events:

1. User opens `/foodevents` or `/educationalexpo`.
2. User purchases a ticket through the mock Stripe checkout.
3. The page refreshes payment state with `paymentsApi.myPayments()`.
4. User can then register/join the event.

If the user clicks register before purchasing a ticket, the page shows a message asking them to buy a ticket first.

## Security Notes

- The frontend route guards are convenience and UX checks; backend role checks are the security boundary.
- `AdminProtectedRoute` verifies admin status with the backend before rendering `/adminpanel`.
- Tokens are stored in `localStorage`, so XSS protection matters.
- The backend URL is hardcoded; avoid pointing production builds at a development API.
- Mock Stripe checkout and social/admin helper UIs are not production integrations.

## Troubleshooting

| Issue | Fix |
| --- | --- |
| API calls fail with connection errors | Start the backend at `http://127.0.0.1:8000` or change `BASE_URL`. |
| User is redirected to login | The token is missing, expired, invalid, or the API returned `401`. |
| Admin panel redirects home | `GET /auth/me` did not return an admin user. |
| Role dashboard redirects | Check `viventAuthRole` and the route's allowed role list. |
| Food/educational register button does not join | Purchase a ticket first, then register. |
| Job fair CV does not appear in backend data | CV selection is frontend-only in the current implementation. |
| Lint fails | Run `npm run lint` and fix reported JS/JSX issues. |

## Known Implementation Gaps

- No Vite `.env` configuration is used for the backend base URL.
- No automated frontend test suite is present.
- Several exported helper functions in `src/utils/api.js` are legacy or future-facing and do not match active backend routes.
- No real file upload/storage flow exists for job fair CVs or event media.
- Admin post-management and client-analytics sections include local UI state and are not fully backed by current API routes.
- Mock Stripe and mock social OAuth are development simulators.
